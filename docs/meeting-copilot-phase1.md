## Selected implementation (before code changes)
Ordinary microphone -> AudioWorklet PCM -> independently valid <=10-second WAV requests -> existing server OpenAI credentials, gpt-transcribe bounded file transcription. Rolling transcript updates per completed chunk, NOT token-level realtime captions. This is an explicit Phase 1 latency tradeoff; no unsupported long websocket process. Official file-transcription guide https://developers.openai.com/api/docs/guides/speech-to-text; true live alternative https://developers.openai.com/api/docs/guides/realtime-transcription uses gpt-live-transcribe and separate session infrastructure. No speaker diarization claim. No TTS. No system/remote call capture: speakerphone may be audible; headphones may omit remote audio.

Server resolves exact appointment from canonical Diary and its exact relationship context before preparing/start. Proposed session/usage schema provides named-user ownership, one live session per user, quota reservations before provider spend, sequence replay protection, bounded lifetime, draft/live/review/approved state. Client holds transcript in memory while live; no raw audio stored, no transcript auto-save. Browser navigation/reload loses unapproved transcript; explain it. Server retains only appointment/context metadata and usage unless explicit review approval; approved meeting summary is an existing canonical Meeting note with session/appointment provenance. Actions require separate existing guarded task confirmation. Next-meeting candidates cannot become confirmed without reliable speakers and explicit date/acceptance review; no automatic Diary or calendar write. Existing Phase 2 Diary storage migration is unapplied: Add to Diary remains an explicit existing manual workflow, not an implicit dependency migration.

Provider failure: mark exact transcript gap, keep transcript and review usable; no silent retry of billed chunks. End/navigation stops microphone synchronously; final in-flight result can settle before review. Analysis returns only transcript/context-cited candidates; max two questions. Candidates are never facts until explicit approval; prevent promotion when exact appointment/linkage no longer matches.

## Implemented boundaries and acceptance gates
- Proposed migration: `20261025180100_meeting_copilot_phase1.sql`, UNAPPLIED hosted. Two private RLS-enabled service-only tables (sessions, usage), a session/quota command RPC, and an atomic promotion bridge calling the existing `apply_relationship_workspace_action`. No changes to existing source/messaging/Diary SQL. Context stores exact appointment/relationship metadata and source IDs, not copied historical message bodies.
- Named-user 600-minute monthly processed-audio allowance across organisations; at most one live session per user and 90-minute session lifetime. Exact PCM byte length establishes audio seconds. Quota is reserved before provider calls; failed attempts remain reserved, never silently retried/refunded. Session started/ended timestamps record elapsed wall time. Live reasoning at most once per 30 seconds of supplied audio; one final reasoning claim per session, max 120 monthly final reviews. Measured reasoning tokens and transcription tokens where provider returns them (otherwise NULL). No UI monetary cost. This does not implement a new paid-seat entitlement system or prove physical identity/password non-sharing.
- Summary approval is atomic with an existing canonical Meeting note and source-revision lock. Stale review, changed appointment/identity or membership fail closed. Navigation locator/title may change on lazy workspace creation; exact source/relationship/date/provenance remain strict. User-approved tasks reuse existing relationship_tasks with named owner and no inferred deadline. Ask Root receives the existing note projection; no second reader/memory is introduced.
- Next-meeting output remains uncertain because neutral audio has no verified speaker identity. User must verify separate acceptance and explicitly enter date/time in the reused existing Diary form. This needs the separate PR #102 Phase 2 Diary migration, which is not applied in Production. No AI-created confirmed appointment or Calendar write.
- Transcript exists in page memory, not browser persistent storage. Independent audio chunks are discarded after processing. Root does not retain raw audio. The external processor's account data-retention settings still apply; no claim of provider zero retention. Approval retains transcript only when its separate checkbox is selected. Unapproved transcript is lost on reload/navigation; clear UI warning.
- End stops mic tracks immediately, flushes the final partial chunk, then visibly settles bounded already-captured queued work before review. Unmount/pagehide stops mic and discards not-yet-started uploads; a bounded provider request already accepted may finish, but stores no audio/transcript. There is no background listening or automatic speech.
- Real authenticated provider/microphone round trip and hosted canonical approval cannot be certified before separately authorized schema deployment. Do not manufacture Auriel meeting content before her real call. All acceptance transcripts in tests/harness are conspicuously SYNTHETIC.
