# LinkedIn Outreach Console

Route: `/dashboard/responses/linkedin`, linked from Responses and the dashboard's New LinkedIn connections card. Existing inbox and inbound reply workflows remain intact. Inbound reply context is a compact count beside collapsed queue diagnostics. The batch list and selected workspace stay on the same console route.

The queue is a read-only view of `buildContactLifecycle`, with `planManualCompletion` eligibility and existing due dates. It does not persist another lifecycle. Each batch contains up to ten contacts. Overdue follow-ups precede first messages; recorded leadership role matches then precede other first messages. Dates and stable contact identity break ties. No AI score is created.

Fresh means acceptance/detection within the last seven days, inclusive; older, missing or future acceptance timestamps use catch-up wording. A first message requires a recorded acceptance and verified LinkedIn identity so existing reconciliation can create/reuse the cadence safely. Missing identity and unreconciled legacy follow-ups are counted separately with a Growth reconciliation link. Follow-ups require a canonical growth action and actual projected due status. Replies, engagement, closure, nurture, source-owned actions, explicit next-step overrides and invalid lead quality suppress outbound work.

Generation reuses `responseDraftRules`, `safeLinkedInFirstMessage`, organisation generation context and the existing Responses model. It identifies the actual growth stage and recorded history, adds catch-up timing rules, and checks revision again after generation. Drafts are cached per contact and cadence stage while the page is open, so selecting another batch row preserves edits. Generation errors allow manual writing; no draft persistence or provider sending is implied.

Open & Copy opens the stored validated HTTPS LinkedIn messaging URL, falling back to recorded canonical profile evidence, and copies the current edited text. The new tab is opened within the user gesture to avoid clipboard-await popup blocking. Clipboard errors preserve and select the text for ordinary copying. Missing destinations never generate an invented conversation URL. Navigation, copying, generation and skipping have no lifecycle mutation path.

Mark sent & next is explicit human confirmation of the actual provider send. It records the click time and edited message using `completeManualAction`, its revision lock, atomic `record_manual_completion` RPC, persistent receipt history and reconciliation. Retry reuses the same receipt, timestamp and message. The server checks queue eligibility again before a new completion, including human replies. Successful confirmation moves to the next card without page navigation; reconciliation errors stop the flow and instruct safe reload. No new migrations or cadence intervals are introduced. Existing main uses weekly follow-ups despite historical day-number stage labels; this implementation preserves that actual behaviour.

Tenant write membership is verified before snapshot reads, generation or completion. No LinkedIn sending API, scraping or LinkedIn browser automation is implemented. The human must paste and click Send in LinkedIn before Mark sent. Browser popup/clipboard permissions may require the displayed manual fallback controls.

Only captured Ops records are available. Intake remains unchanged and can miss connections. Sessions remember skips only while the page is open. A new batch retains the view; a separate control includes skipped contacts again. The console conservatively excludes ambiguous or source-owned records rather than silently changing their lifecycle.

## Workbench and self-contact repair

The desktop console shows the complete current batch as selectable rows beside the selected message workspace. Each row shows name, recorded company/role, Fresh/Catch-up/Follow-up, actual cadence stage and due/acceptance date. Selection is presentation-only. Skip removes the selected row locally and chooses its successor; confirmed completion removes it immediately and refreshes the remaining batch against current server evidence without refilling it or changing route/filter. Edited drafts survive row switching. The selected identity and primary actions sit together in a persistent header; only the message/history body scrolls on desktop. Reconciliation details are collapsed and do not disable valid work. Inbound replies are compact context, with the explicit Back to Responses inbox link for navigation.

The previously visible owner record already had an active, overdue day3_dm growth action, so it satisfied lifecycle/due eligibility. The original queue checked lifecycle ownership but never compared the contact with sender/owner/account identity. The repair loads the tenant's saved yourName, businessName/contactEmail, organisation name, connected LinkedIn page_name/page_id and verified auth metadata/email for the current user and this tenant's owner members. Exact normalised person/organisation names, email addresses, recorded LinkedIn profile evidence and provider IDs suppress self contacts before batching. Company-only or domain-only matches do not suppress other people. Both queue reads and generation/completion eligibility use this server-loaded identity; callers cannot supply the exclusion evidence. Reads select no provider credentials and auth metadata is never included in queue JSON. Existing duplicate completion receipts remain retryable without advancing again. No hard-coded person, organisation, profile slug or account ID is used.

Regression coverage includes the ten rendered rows, selected highlight/context, selection without lifecycle writes, successor selection after Skip/completion, separate-tab Open & Copy, toolbar/header placement, compact non-blocking diagnostics, authenticated tenant self-identity reads and self-contact suppression. Real sends are never performed as a browser test.
